## 1. 질문

원 R6에서 대조군 세포를 입력으로 쓰는 모델(B00)은 세포주 평균과 Ridge보다 전체 RMSE가 낮았다. 이 후속 분석은 그 이득이 무엇에서 왔는지를 묻는다.

1. 그 이득은 **약물별로 다른 반응**을 맞혀서 생겼는가, 아니면 **같은 대조군 pool(plate × 세포주)의 모든 약물에 공통인 이동**을 맞혀서 생겼는가.
2. 약물 입력을 아예 주지 않은 모델, 세포 집합의 평균만 본 모델, 선형 모델은 같은 조건에서 얼마나 따라오는가.
3. 그 답에 따라 **하나의** 다음 변경을 고른다 (약물 차이를 직접 학습 / plate 이동 / 세포 수×분자 수 예산).

## 2. 용어

- **조건**: (세포주, 약물 구조 그룹) 하나. 채점하는 행.
- **pool**: 한 plate의 한 세포주 DMSO 대조군 세포 전체. 조건의 pool은 그 조건의 주 plate의 pool이다. 유효 pool 234개.
- **전체 RMSE**: 조건별로 2,000개 유전자에 대한 RMSE → 약물 그룹 안에서 평균 → 약물 그룹 사이 단순 평균.
- **pool 내 대비 RMSE (L_within)**: 같은 (fold, pool)에서 평가된 약물들에 대해 정답과 예측을 **각자 자신의 평균으로** 중심화한 뒤 조건별 RMSE를 구하고 위와 같은 순서로 평균한다. pool의 모든 약물에 같은 값을 더하는 예측은 이 값을 바꾸지 못한다. 약물이 2개 미만인 그룹은 기여하지 않는다. "같은 학습 평균을 양쪽에서 뺀 RMSE"는 전체 RMSE와 같은 양이므로 특이성 지표로 쓰지 않는다.
- **retrieval**: 예측을 같은 후보 집합의 측정 반응들과 비교해 자기 약물의 순위를 본다. 동점은 평균 순위로 보정한다(top1 = [더 나은 후보 0개]/동점 수 등). 원 R6의 계산은 `legacy_*` 이름으로만 남긴다. 후보 집합은 세 가지를 따로 보고한다: 같은 세포주 전체(`line_all`, 원 방식), 같은 pool·세포주 중심화(`pool_linecentred`), 같은 pool·pool 중심화(`pool_centred`).
- **차이의 부호**: 항상 `후보 − 비교군`. RMSE는 음수가 후보 우세, retrieval은 양수가 후보 우세.
- **판정 범주**: 운영 기준은 비교군 대비 1%. 구간 전체가 −1% 아래면 `improved_operational`, 구간이 0 아래지만 −1%에 못 미치면 `improved_small`, 구간이 ±1% 안에 있으면 `no_large_gain`, 0을 포함하고 ±1%를 넘으면 `uncertain`, 반대 방향은 `worse_small`/`worse_operational`. 이 기준은 완화하지 않는다.
- **구간**: 약물 구조 그룹을 단위로 한 bootstrap 2,000회의 2.5–97.5 백분위. 세포, 박화 seed, 학습 seed는 독립 표본이 아니므로 조건 안에서 먼저 평균한다. 재표집마다 pool 중심을 다시 계산한다.

## 3. 데이터와 분할

원 R6의 계약(대조군 count cache, 정답, 분할, 평가 view)을 **읽기 전용으로 그대로** 쓴다. 새로 내려받은 데이터는 없다.

- 약물 그룹: 학습 209 / 검증 70 (어느 단계에서도 쓰지 않음) / 시험 70.
- **source fold**: 학습 약물 209개 안의 구조 그룹 fold 3개 (`fold = floor(blake2b('r3-devfold|'+SMILES)·3)`, 계약에 이미 있는 규칙; 반응값은 들어가지 않는다). fold k의 held 약물은 fold k, fit 약물은 나머지 학습 약물.
- **inner dev**: 각 fold의 fit 약물 중 `blake2b('r6f-inner|'+SMILES) < 0.2`인 약물. 학습률·벌점 선택에만 쓴다.
- 반응에서 계산하는 모든 양(평균, 축소 강도, 표준화 척도, Ridge 벌점, 앵커)은 fold마다 **fit 약물만으로** 다시 구한다.
- 시험 약물 70개는 이미 한 번 채점된 집합이다. 이 분석에서는 (a) 기존 예측의 원인 진단 표, (b) 동결 커밋 뒤 한 번의 "기존 벤치마크 후속 평가"에만 쓰고, 설정 선택에는 쓰지 않는다. 모든 표에 `split_role`을 적는다.

## 4. 단계

| 단계 | 내용 | 새 학습 |
|---|---|---|
| A | 기존 예측만으로: pool 평균 기준선, 단일/다중 plate, pool 내 대비, retrieval 후보 비교, 고정 checkpoint 민감도(h=0, 약물 교환), 양성 대조 | 없음 |
| B | 통로 확인: fold 2, seed 42, inner dev로 S/SD/M/R 한 번씩과 학습률 후보 | 소수 |
| C | 확인: source fold 3개 × seed 42/43/44에서 S/SD/M (신경망 27회 이내) + fold·seed별 Ridge | 27회 이내 |
| D | 분기 선택(아래 6절)과 실행. 분기는 최대 2개 | 분기별 |
| E | (선택) 동결 커밋 뒤 기존 벤치마크 후속 평가 한 번 | 동결 목록만 |

### 4.1 단계 A의 표

- `pool_contract.tsv`: pool별 세포 수, 역할별 세포 수, 약물 수, 단일/다중 plate 여부.
- `pool_baselines.tsv`: 무변화, 전체 평균, 세포주 평균, pool 평균, 축소 pool 평균(κ ∈ {0, 2, 8, 32, ∞}; κ는 source out-of-fold 전체 RMSE로만 고른다)과 기존 모델 예측.
- `single_vs_multiplate.tsv`: 세포주가 plate 하나에만 있는 조건과 여러 plate에 있는 조건을 나눈 같은 표.
- `within_pool_contrasts.tsv`, `retrieval_pool_vs_global.tsv`: 2절의 정의대로.
- `checkpoint_branch_sensitivity.tsv`: 원 R6 checkpoint에서 약물 부분 h를 0으로 둔 예측, 같은 대조군에서 약물만 바꿨을 때 예측 변화. 함께 학습된 모델의 민감도이지 "약물 입력 없이 학습한 모델"의 성능이 아니다(그것은 S 팔).
- `positive_control_calibration.tsv`: 학습 약물의 처리군 well과 기준 대조군을 바코드가 겹치지 않게 반으로 나누어, 한쪽 반으로 다른 쪽 반을 "예측"했을 때 지표가 반응하는지 본다. **독립 배양 반복이 아니라 한 well의 기술적 분할**이다. 같은 약물이 두 plate에 있는 경우만 반복에 가까운 단위로 따로 보고한다.

### 4.2 단계 B–C의 팔 (자세한 계약은 `ARM_CONTRACT.tsv`)

| 팔 | 대조군 입력 | 약물 입력 | 구조 |
|---|---|---|---|
| S | count 집합 (B00과 같은 encoder) | 없음 (학습되는 상수 벡터) | B00 head |
| SD | count 집합 | ECFP4 | 원 R6 B00 그대로 |
| M | 집합의 평균 log 발현만 (2층 MLP) | ECFP4 | B00 head |
| R | 집합의 평균 log 발현 | ECFP4 | 두 블록 Ridge |

공정성 장치: 네 팔은 **같은 저장 view**(seed별·pool별 8회 × p 3개 = 24개, fit_input 세포 64개씩; 생성기 `PCG64([20261118, seed, pool, 1000p, rep])`)를 쓴다. 신경망 세 팔은 같은 seed에서 같은 배치 순서(view, 조건)를 받는다. 목적함수, 갱신 수, epoch 수, 최적화기는 같다. 평가는 원 R6의 고정 eval_input 세포 64개와 저장된 박화 view(p=1 seed 0; p=0.5·0.25 seed 0–2)이다.

## 5. 금지와 규율

- 시험 약물로 설정을 고르지 않는다. 원 R6 자산·다른 브랜치·다른 작업의 job을 건드리지 않는다.
- 부정 결과는 끝난 부정 결과로 적는다. 자동으로 다음 실험을 붙이지 않는다. 실행하지 않은 분기는 `NOT_RUN.md`에 적는다.
- 관측 / 구현 사실 / 가설 / 미확인을 구분해서 쓴다.
- 공개 저장소에는 코드, 설정, manifest, 해시, 작은 표·그림, 보고서만 올린다. count·발현 배열, checkpoint, 기획 문서는 올리지 않는다.
- 계산은 Slurm으로만. 이 연구의 job 이름은 `r6f_`로 시작하고 GPU는 동시에 2개까지만 쓴다. run ID는 덮어쓰지 않는다.

## 6. 분기 선택 규칙 (source 결과로만 고른다)

`DECISIONS.md`에 관측 → 해석 → 고른 분기 → 다른 분기를 고르지 않은 이유를 **실행 전에** 적는다.

| source에서 본 것 | 분기 |
|---|---|
| SD가 S보다 pool 내 대비에서 뚜렷이 낫지 않다 (약물 입력이 쓰이지 않는다) | F1: pool 평균을 앵커로 두고 약물 간 차이를 직접 학습하는 손실 |
| 전체 RMSE 이득이 pool 평균으로 설명되고, 처음 보는 plate로 옮길 때 무너진다 | F2: plate 이동 평가 |
| 집합 모델이 평균 모델보다 낮은 관측량에서만 낫다 / 관측량 의존이 보인다 | F3: 세포 수 N × 유지율 p 예산 (추론 전용 2×2는 병행 가능) |
