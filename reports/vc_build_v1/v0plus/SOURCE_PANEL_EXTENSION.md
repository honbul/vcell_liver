# 공개 약물 반응 학습 자료 확장과 CTRPv2 정정

기존 GDSC2·CTRPv2·PRISM 학습 코어는 LIMORE에서 구조를 확인한 68개 약물에 한정돼 있었다. 같은 학습 세포 ID와 원자료만 사용해 기존 패널 밖에 있는 CTRPv2·PRISM 단일 약물 측정을 추출했다. 기존 세포 1,014개와 계통 991개 안에서 추가 표를 만들었고, 성인 HCC 21계통도 기존과 같다. HCC 측정 수는 같은 계통에 더 많은 처리를 연결했다는 뜻이다. 외부 확인 코호트의 반응이나 발현은 사용하지 않았다. [기존 원본·입력 해시](../data_function/cross_receipt.json)

| 소스 | 추가 약물 | 추가 실측 행 | 성인 HCC 실측 행 | 성인 HCC 지원 ≥8계통 약물 |
|---|---:|---:|---:|---:|
| CTRPv2 | 446 | 255,185 | 6,821 | 380 |
| PRISM20Q2 | 664 | 291,244 | 8,778 | 652 |
| 두 소스 합계 | 1,061 | 546,429 | 15,599 |  |

공통 49약물은 두 소스 모두에 성인 HCC 측정이 있다. 합계의 HCC 행은 소스별 측정 수의 합이다. 추가 파일은 880개 세포·860개 계통에서 얻었다. 기존 코어의 정확한 GDSC2 parent는 42개이며, 전체 원표의 native 약물 ID 295개는 별도의 구조 연결이 필요한 범위다. [확장 영수증](source_panel_extension_receipt.json) · [공식 GDSC2 측정 설명](https://depmap.sanger.ac.uk/documentation/datasets/drug-sensitivity/)

CTRPv2 SNP fingerprint와 PRISM STR QC 및 기존 농도 구간 규칙을 유지했다. 제조사 원 화합물 ID별로 구조가 유일하고 혼합물 표기가 없는 기록만 사용했다. 중원자 8개 이상인 서로 다른 유기 조각이 두 개 이상이면 보수적으로 제외했다. 이 규칙은 일부 복합 염도 제외할 수 있다. 공급원에 단일 약물이라고 명시된 나머지를 정확한 parent InChIKey로 정규화했다. 신규 약물의 SMILES와 표적 원주석은 원본 측정과 함께 G1에 보관한다.

## 기존 학습 코어에서 발견한 혼합 처리

다중 조각 구조에서 최대 parent를 고르는 함수가 CTRPv2 혼합물에도 적용됐다. Vorinostat의 전체 카탈로그 재집계에서 단독 측정 대신 혼합 측정 ID가 선택되는 현상을 먼저 확인했다. 혼합물을 native ID에서 제외한 뒤, 기존 코어 자체를 점검해 아래 두 원자료에서 같은 유형의 오류를 확인했다. [코어 정정 영수증](source_panel_correction_receipt.json)

| 기존 등록 약물 | 실제 혼합 처리 | 제외 ID | 제외 행 (HCC) | 순수 약물 ID | 교체 행 (HCC) |
|---|---|---:|---:|---:|---:|
| Navitoclax (ABT-263) | JQ-1 + navitoclax | 660252 | 694 (19) | 362342 | 688 (18) |
| Rapamycin | sirolimus + bortezomib | 660134 | 700 (19) | 56703 | 699 (19) |

해당 두 그룹은 기존 CTRPv2 코어의 1,394행이며 전체 기존 코어 65,685행의 2.12%다. 등록 당시의 LIMORE, Wong, LICOB 및 개발 성적은 이 코어를 사용했다. 순수 단일 약물로 적합한 모델의 성적으로 인용할 때 제약이 있다. G1에서 원래 64,291행의 값과 두 약물의 검증된 단일 측정 1,387행을 결합해 정정 코어 65,678행을 고정했다. 정정 코어와 추가 표를 함께 쓰면 1,129약물·612,107행이다. 전체 표와 체크포인트는 G1에 보관한다. 이전 예측에서 오류의 크기나 성적 변화 방향은 이 감사만으로 추정할 수 없다.

진단 작업 `33107`은 전체 카탈로그에서 원래 68약물의 측정 재현 검사를 통과하지 못했다. `33119`에서 변화한 소스 지지를 집계했으며 혼합물 제외 전 값으로 기록했다. 최종 `33120`은 native ID의 혼합물을 제외한 추가 테이블을 작성했다. 정정 코어는 `33121`에서 생성했다. 공용 소스 등록 경로의 혼합물 검사도 수정했다. [작업 원장](RUN_LEDGER.tsv)
