# NODE RNA 복구와 미채점 LICOB 공여자 9명 확인

동일 SHA-256을 가진 두 번의 공개 NODE 다운로드에서 파일 전체 MD5가 배포값과 달랐다. RNA 워크시트를 포함한 압축 스트림은 41,943,040바이트 위치의 8 MiB 손상 구간에 걸친다. 공개 API는 해당 구간의 Range 요청에도 전체 길이 HTTP 200을 응답했다. 이번 회차는 손상 시작점 **앞의 실제 DEFLATE 바이트**를 펼쳐 완결된 XML 행만 쓴다. 65개 표본 열의 주소, 데이터 14,799행의 연속 번호, 유일 유전자·완전 숫자, 소스 RNA와 공통 유전자 7,123개를 검증한다. 이 범위의 부분 복구에는 워크시트 전체 CRC 인증을 붙이지 않는다. 독립 배포 경로인 저자 iLICOB의 동일 50개 RNA에 대한 샘플 내 순위 상관의 중앙값 ≥.95, 5백분위수 ≥.90을 요구한다. 이 검산에 약물 반응은 사용하지 않는다. [원본 무결성 감사](STEP1_SCALE_AND_LICOB.md) · [저자 RNA 등록](LICOB_AUTHOR_PROTOCOL.md) · [NODE 공개 파일](https://www.biosino.org/node/api/download/node/data/public/OED00796358)

- 기존 34모델·29환자 RNA의 외부 성적과 이번 선행 감사의 S6 값 노출 범위를 구분한다. 이번 등록은 S1의 성인 HCC·공여자 표와 S6의 표본 ID 열·약물 헤더만 사용한다. 원래 S6을 채점하지 않은 성인 HCC 공여자 9명(각 1오가노이드)은 주 확인 패널이다. 기존 저자 RNA 평가의 공여자 29명과 겹치지 않아야 한다. 기존 29명 및 전체 38명(43모델) 결과는 기술 표다. 서로 다른 HCC 연구 간에는 공용 공여자 식별자가 없다. 새 9명은 같은 LICOB 연구의 다른 환자다.
- 53개 약물은 기존 S5/S6 exact parent 등록을 그대로 사용한다. 주 확인은 9×53=477개 연속 음의 생존 AUC다. 약물·환자별 가중은 기존과 같다. 환자 내 점수는 동일 환자의 여러 오가노이드를 먼저 평균하고 약물 평균의 상수를 보존한다.
- **주 확인 후보는 2D 정정 코어만으로 적합한 구조 커널**이다. 벌점 4, 잔차 배율 1, RNA·ECFP·경로/TF·약물 표적 및 Chronos/변이/CNV 간접 RNA 특징을 기존대로 사용한다. LIMORE에서 높았던 약물 내 성적을 근거로 지정한다. 기존 설정으로 약물 평균, 약물별 Ridge, CellHit, Velodrome inductive, CODE-AE inductive, V0+ inductive를 같은 7,123개 RNA 축에서 다시 적합한다. 고정 보조 후보는 Ridge+구조 커널 50:50, 표적 발현 항, 표적 발현+실측 코딩 변이 및 같은 DNA 순열 대조다. 실측은 복구 워크북 내 CRC 검증된 D시트에서 가져온다. 가중·형상은 실측 유전체 비교와 같다. 새 대상의 결과를 보고 후보·격자·축을 고르지 않는다. [구조 커널 개발](STRUCTURED_CV_RESULTS.md) · [실측 유전체와 표적 명세](MEASURED_DRIVER_PROTOCOL.md)
- 사전 판정은 새 9명에서 주 후보가 약물 평균·Ridge·CellHit 각각보다 약물 내 Spearman/Pearson과 환자 내 Spearman/NDCG@5 네 지표의 95% 짝지은 하한에서 모두 0을 넘는지다. Precision@5 및 기전군별 결과를 함께 보고한다. 환자·약물 교차 재표집과 환자 재표집을 기존대로 사용한다. 같은 LICOB 연구의 재구성된 발현 패널에서 얻는 판정이며, 별도 연구 재현이나 배포 CLI의 원시 RNA 입력 검증은 각자의 증거가 필요하다. 제출한 컴포넌트의 해시·행을 검증하여 공동 동결 후 한 번 별도 채점한다.
