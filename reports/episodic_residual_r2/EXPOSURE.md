# 연구 R2 — 자료 노출 기록 (EXPOSURE)

**작성일:** 2026-11-17 · HCC 평가 **전에** 작성했다.

## 1. 한 줄 요약

이 연구의 HCC 평가는 새로 숨겨 둔 시험이 아니다. **이미 한 번 채점된 공개 벤치마크를 다시 쓰는, 동결 후 평가(post-freeze evaluation on a reused public benchmark)** 다.

## 2. 무엇이 이미 노출됐나

| 항목 | 상태 |
|---|---|
| HCC 세 계열(HUH7, JHH5, JHH7)의 Level 3 자료 | 앞선 연구 B(`d67bf68`)에서 내려받아 처리했고 시험 분할까지 채점했다 |
| 시험 분할(약물 그룹 단위, split seed 1–3) | 연구 B의 것을 **그대로** 쓴다. 연구 B에서 이 분할로 무변화·같은 약물 평균·mean-offset·fine-tuning 점수를 이미 봤다 |
| 이 연구의 설계 동기 | "세 계열 모두 mean-offset이 full fine-tuning보다 낮았다"는 연구 B의 HCC 시험 결과에서 나왔다. 즉 **과제 정의와 비교 기준선의 선택 자체가 HCC 시험 결과의 영향을 받았다** |
| HCC 검증 약물(연구 B가 학습률·중단 선택에 쓴 것) | 이 연구에서는 선택에 쓰지 않는다. 보조 query로만 채점한다 |

## 3. 이 연구에서 지킨 것

- 동결 전에는 HCC 발현 값을 한 번도 읽지 않았다. HCC 값을 여는 함수(`target.load_target`)는 (a) `freeze_manifest.json`이 Git에 올라가 있고 (b) 최종 평가 작업이 설정하는 환경 변수가 있을 때만 동작한다. 실제 store에 대한 fixture가 "동결 전에는 열리지 않는다"를 확인했다(`leak_fixtures.json`).
- f0(source 같은 약물 평균), feature 축, 학습된 모델, λ·κ·학습률·update 수·BatchNorm 처리·중단 시점·모델 선택은 **모두 161개 source 세포주만**으로 정했다. 세 HCC 계열은 source에 없고, 서로의 처리 후 RNA를 주고받지 않는다.
- target에서 쓰는 처리 후 라벨은 K개 support가 전부다(K=8/16/32, 같은 순서의 앞 K개). target 검증 라벨은 0개다.
- 동결 뒤에는 방법을 고치지 않는다. 평가 코드에 오류가 있어 고쳐야 하면 이유를 실행 기록에 남긴다.

## 4. 그래도 남는 한계

- 같은 벤치마크를 두 번째로 쓰는 것이므로, 여기서 얻은 HCC 점수는 **독립적인 확인이 아니다.** 방법 선택이 간접적으로 이 자료에 맞춰졌을 가능성을 배제할 수 없다.
- support 16개는 연구 B의 적응 약물과 같은 약물 그룹이다(같은 순서 규칙). 연구 B의 점수와는 라벨 비용(연구 B는 검증 라벨을 추가로 씀)과 채점 단위(연구 B는 화합물 ID 단위, 이 연구는 약물 그룹 단위)가 달라 **직접 비교하지 않는다.**
- 독립적인 확인이 필요하면 이 연구에서 한 번도 쓰지 않은 세포주·자료가 필요하다. 이번에는 하지 않았다.
